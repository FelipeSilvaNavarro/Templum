# Kanban v2: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Kanban card 40: a card can be for anyone, any session of an agent, or one block; it gets a priority, a
checklist and its id on its face and in its dialog; dragging a card near an edge scrolls the column or the board; the
open card is redone with its buttons where they belong; agents read and set all of it.

**Architecture:** The model stays in `board.rs` (pure, serde): `Card::assignee` becomes an `Assignee` (a block or an
agent, saved as one string), plus `priority` and a `checklist` of `checklists::Item`s with ids from the boards'
`next_id`. `kanban.rs` draws the face, the dialog and the edge scrolling (one `ScrollHandle` per scroll container, kept
with `window.use_keyed_state`, moved each frame while a drag holds the pointer near its edge). The agents' tools gain
`priority`, `for` and items in `templum-mcp` (`NewCard`, `CardEdit`, the `templum kanban` verbs) and
`workspace/content.rs` applies them; `claim_card` matches the caller's agent (`Pane::agent`).

**Tech Stack:** Rust 2024; GPUI (gpui-fast 0.1.8) through gpui-kit `=0.7.3`: `on_drag_move::<T>` (capture phase, every
listener of that drag type: gpui-fast-0.1.8 `src/elements/div.rs:361`), `ScrollHandle` (`offset`, `max_offset`,
`set_offset`) with `track_scroll`, `window.use_keyed_state`, `window.request_animation_frame`, gpui-kit's `Button`
(`primary`, `ghost`, `small`, `outline`, `dropdown_caret`, `DropdownMenu::dropdown_menu`), `PopupMenu` (`item`,
`label`, `separator`, `submenu`, `PopupMenuItem::checked`), `AlertDialog` (`title`, `description`, `footer`, `w`),
gpui-base's `actions::Confirm`; `templum_canvas::edge_scroll`; serde; the headless tests of `workspace/tests/`.

**Spec:** [docs/specs/kanban.md, Version 2](../specs/kanban.md#version-2-kanban-card-40) (layout and sizes: read it
before any UI task) and [docs/specs/connections.md, Cards for an agent](../specs/connections.md#cards-for-an-agent)
(the tools' exact arguments and answers).

## Global Constraints

- `boards.json` stays `"version": 1`. A card writes `priority`, `assignee`, `checklist` only when set; an agent
  assignee is the string `"agent:<id>"`, a block one its bare block id; an unknown priority reads as none.
- Ids of checklist items come from `Boards::next_id`: unique across boards, columns, cards and items, never reused.
- Priority words: `low`, `medium`, `high` (titles Low, Medium, High); `none` clears it in the tools. Nothing sorts by
  priority.
- Colors: priority Low `ui.title_dim`, Medium `palette.ansi[3]`, High `palette.ansi[1]`; Delete card
  `palette.ansi[1]`; checklist done and all-done progress `ui.accent`.
- Icons (gpui-kit `IconName`, all lucide icons are registered through `AllAssets`): `SignalLow`, `SignalMedium`,
  `SignalHigh`, `ListChecks`, `MessageSquare`, `FileText`, `Trash`, `Check`, `Close`.
- Zoom scales like a photo: every size on a card or a board is a world size × `z`; the dialog is at the window's
  scale. Edge scrolling uses `templum_canvas::edge_scroll` in world units (zone 40, speed 900 per second at `z` = 1).
- Every change from the dialog or a tool is one step of the kanban's Ctrl+Z (`Workspace::edit_boards`), except the
  typing in the title and description (one step at the first change, as now: `edit_typed`).
- Copy: dialog title `Card #<id>`, description `In <column> on <board>`; the assignee shows `Anyone`, `Any <agent
  title>` or a block's title; agents' answers exactly as connections.md's "Cards for an agent" writes them.
- Only `crates/templum` uses gpui-kit; no new dependency; no `unsafe`.
- Each commit passes `cargo fmt --all && cargo clippy --workspace --all-targets -- -D warnings && cargo test
  --workspace`, on `development`, titled as CLAUDE.md says. Task 9 runs `--bench` and `--bench-mixed` (painting
  changes).

## Review Focus

1. **An agent changes the card while the person has it open** (adds items, moves it, sets its priority): the dialog
   shows the change at once and the person's fields keep their text. Task 4 pins items added meanwhile.
2. **The card is deleted while its dialog is open** (by an agent, another block, Ctrl+Z): the dialog draws without
   it and Done still closes. Task 3 pins it.
3. **The drag ends near an edge** (dropped, or Esc): scrolling stops at once and asks for no more frames. Task 8 pins
   it.
4. **A small block at far zoom** (420 × 280 at zoom 0.25): a card list shorter than its two edge zones doesn't
   scroll from its middle. Task 8's unit test pins it.
5. **An assignee no workspace has** (a closed block, a stopped workspace's): the face and the menu show its id
   instead of dropping it. Tasks 2 and 5 pin it.

**Interfaces:**
- Consumes: `crate::checklists::Item` (`id: u64`, `text: String`, `done: bool`, serde as checklist blocks write it).
- Produces (in `board.rs`):
  - `pub(crate) enum Assignee { Block(String), Agent(String) }`: `Clone, Debug, PartialEq, Eq, Serialize,
    Deserialize`, `#[serde(from = "String", into = "String")]`; `impl From<String> for Assignee` (a `agent:` prefix
    gives `Agent`, anything else `Block`) and `impl From<Assignee> for String`.
  - `pub(crate) enum Priority { Low, Medium, High }`: `Clone, Copy, Debug, PartialEq, Eq, Serialize, Deserialize`,
    lowercase; `pub const ALL: [Priority; 3]`, `pub fn name(self) -> &'static str` (`"low"`), `pub fn title(self) ->
    &'static str` (`"Low"`), `pub fn named(name: &str) -> Option<Priority>` (trimmed, either case).
  - `Card { …, pub priority: Option<Priority>, pub assignee: Option<Assignee>, pub checklist:
    Vec<checklists::Item>, … }`; `priority` read through a `known_priority` deserializer (unknown: none, as
    `known_label`).
  - `impl Card { pub fn progress(&self) -> (usize, usize) }` (done, all).
  - `impl Boards { pub fn add_items(&mut self, board: u64, card: u64, items: &[(String, bool)]) -> Vec<u64>; pub fn
    set_item_done(&mut self, board: u64, card: u64, item: u64, done: bool) -> bool; pub fn remove_item(&mut self,
    board: u64, card: u64, item: u64) }` (`add_items`: at the end, new ids, empty when the card is gone;
    `set_item_done`: false when the card has no such item).
  - `load` also folds every item id into `next_id`.
